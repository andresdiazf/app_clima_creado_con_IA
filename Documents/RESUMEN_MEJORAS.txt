DESPUÉS:
/**
 * Obtiene los datos meteorológicos actuales para unas coordenadas específicas.
 * 
 * Esta función hace una petición a la API de Open-Meteo para obtener información
 * meteorológica en tiempo real. Incluye validación de coordenadas, manejo de
 * errores y timeout para evitar peticiones colgadas.
 * 
 * @async
 * @param {number} lat - Latitud de la ubicación (-90 a 90)
 * @param {number} lon - Longitud de la ubicación (-180 a 180)
 * @param {Object} [options] - Opciones adicionales
 * @param {number} [options.timeout=10000] - Timeout en milisegundos
 * @param {string} [options.windspeedUnit='kmh'] - Unidad de velocidad
 * @param {string} [options.timezone='auto'] - Zona horaria
 * 
 * @returns {Promise<WeatherData>} Datos meteorológicos actuales
 * 
 * @throws {Error} Si las coordenadas son inválidas
 * @throws {Error} Si la API retorna un error
 * @throws {Error} Si la petición excede el timeout
 * @throws {Error} Si los datos recibidos son inválidos
 * 
 * @example
 * // Obtener clima de Bogotá
 * const weather = await fetchWeather(4.6097, -74.0817);
 * console.log(`Temperatura: ${weather.temperature_2m}°C`);
 * 
 * @example
 * // Con opciones personalizadas
 * const weather = await fetchWeather(4.6097, -74.0817, {
 *   timeout: 5000,
 *   windspeedUnit: 'mph'
 * });
 * 
 * @see {@link https://open-meteo.com/en/docs|Open-Meteo API}
 */

🔧 FUNCIONES AUXILIARES AGREGADAS
═══════════════════════════════════════════════════════════════════════════════

1. validateCoordinates(lat, lon)
   - Valida que las coordenadas sean números
   - Verifica rangos válidos (-90 a 90, -180 a 180)
   - Lanza errores descriptivos

2. isValidWeatherData(data)
   - Verifica que los datos sean un objeto
   - Valida campos requeridos (temperature_2m, weathercode)
   - Retorna true/false

3. fetchWithTimeout(url, timeout)
   - Hace petición fetch con timeout
   - Usa AbortController
   - Lanza error si excede el tiempo

4. getMultipleCitiesWeather(cityNames, options)
   - Obtiene clima de múltiples ciudades en paralelo
   - Retorna array de resultados
   - Maneja errores individualmente

5. checkWeatherServiceAvailability()
   - Verifica si el servicio está disponible
   - Útil para mostrar mensajes de mantenimiento
   - Retorna true/false

💡 EJEMPLOS DE USO
═══════════════════════════════════════════════════════════════════════════════

1. USO BÁSICO
   const weather = await fetchWeather(4.6097, -74.0817);
   console.log(`Temperatura: ${weather.temperature_2m}°C`);

2. CON OPCIONES
   const weather = await fetchWeather(4.6097, -74.0817, {
     timeout: 5000,
     windspeedUnit: 'mph'
   });

3. CON MANEJO DE ERRORES
   try {
     const weather = await fetchWeather(4.6, -74.1);
   } catch (error) {
     if (error.message.includes('coordenadas')) {
       console.error('Coordenadas inválidas');
     } else if (error.message.includes('tiempo límite')) {
       console.error('Timeout');
     }
   }

4. MÚLTIPLES CIUDADES
   const cities = ['Bogotá', 'Medellín', 'Cali'];
   const results = await getMultipleCitiesWeather(cities);

5. CON CÓDIGOS DE ERROR
   const result = await getCityWeatherInfo('Bogotá');
   if (result.error) {
     switch (result.code) {
       case 'INVALID_INPUT':
         console.error('Entrada inválida');
         break;
       case 'GEOCODING_ERROR':
         console.error('Ciudad no encontrada');
         break;
     }
   }

📋 CÓDIGOS DE ERROR
═══════════════════════════════════════════════════════════════════════════════

INVALID_INPUT          - Entrada inválida
EMPTY_INPUT            - Entrada vacía
INPUT_TOO_SHORT        - Entrada muy corta (< 2 caracteres)
GEOCODING_ERROR        - Error al buscar la ciudad
WEATHER_API_ERROR      - Error al obtener datos del clima
INVALID_WEATHER_DATA   - Datos meteorológicos inválidos
UNEXPECTED_ERROR       - Error inesperado
